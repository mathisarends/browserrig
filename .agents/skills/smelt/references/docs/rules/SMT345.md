# SMT345 complexity/excess-positional-parameters

A function accepts more positional parameters than its package allows.

- **Category:** complexity
- **Activation:** policy — style or a package override sets max_positional_parameters, including zero.
- **Severity when active:** warning

## Why

Call sites such as connect(user, run, tab, True) do not say which value is which, and swapping two arguments of the same type still type-checks. max_positional_parameters, set under style or in a style override, is the limit; parameters after that limit must be keyword-only so every call names them. self and cls are not counted, nor are *args and **kwargs. Dunder methods, @overload and @override definitions are exempt because their signatures are dictated elsewhere, and tests are not checked. Positional-only parameters count like any other positional parameter.

## Bad

```python
def connect(user_id: UUID, run_id: UUID, tab_id: UUID) -> None:
    ...
```

## Good

```python
def connect(user_id: UUID, *, run_id: UUID, tab_id: UUID) -> None:
    ...
```

## How to fix

Insert * after the last allowed positional parameter, then pass the remaining arguments by keyword at every call site. Callbacks whose positional signature is fixed by a framework keep it with a reasoned suppression. No automatic rewrite is performed. Enable it for the project with style: {max_positional_parameters: 3}, for one package with a contract, or with rules, which uses a limit of 5.

## Config

- `rules`
- `style.max_positional_parameters`
- `style.overrides`

Explain it in the terminal with `smelt explain SMT345`.
