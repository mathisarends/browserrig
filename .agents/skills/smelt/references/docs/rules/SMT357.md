# SMT357 missing-duration-unit

A numeric duration is named without its unit.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning

## Why

A constant called _FRAME_TIMEOUT = 2.0 does not say whether it means seconds or milliseconds, and code that mixes both converts at every call site until one conversion is forgotten. This opt-in review reports module constants, class fields and function parameters whose name ends in timeout, delay, interval, duration or wait and that hold a number: an int or float annotation, possibly wrapped in Final, ClassVar, Optional, Annotated or | None, or an unannotated int or float literal. Names that end in a unit, such as _TIMEOUT_SECONDS or quiet_ms, and values typed as timedelta are valid. @overload and @override signatures and tests are not checked.

## Bad

```python
_FRAME_TIMEOUT = 2.0


def wait(delay: float) -> None:
    ...
```

## Good

```python
_FRAME_TIMEOUT_SECONDS = 2.0


def wait(delay_seconds: float) -> None:
    ...
```

## How to fix

Append the unit to the name, e.g. _SECONDS or _ms, and convert once where the value enters the code, or type the value as datetime.timedelta. No automatic rewrite is performed. Enable rules: {missing-duration-unit: warning}, or select SMT357.

## Config

- `rules`

Explain it in the terminal with `smelt explain SMT357`.
