# LAY011 layout/misplaced-module-logger

A module logger is declared outside the block immediately after imports.

- **Category:** layout
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning

## Why

Keeping module loggers together after imports makes logging easy to find before constants and other module declarations. This opt-in convention checks direct module-level assignments of logging.getLogger(__name__) in analyzed source files, including annotated assignments and unshadowed import aliases. The import section can include future imports, import-only if blocks and optional imports in try blocks. Comments and blank lines do not affect placement. Other logger names passed to getLogger, custom factories, guarded or local assignments and uncertain bindings are outside scope.

## Bad

```python
import logging

_TIMEOUT_SECONDS = 5
_logger = logging.getLogger(__name__)
```

## Good

```python
import logging

_logger = logging.getLogger(__name__)
_TIMEOUT_SECONDS = 5
```

## How to fix

Place the module logger immediately after the import section and before constants and other code. Review initialization dependencies before moving it, and use a reasoned suppression for intentional exceptions. Enable rules: {layout/misplaced-module-logger: warning} to check the convention. No automatic move is performed.
