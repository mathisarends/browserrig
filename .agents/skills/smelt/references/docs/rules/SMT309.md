# SMT309 layout/module-docstring-convention

A module docstring is missing or present against the package's module_docstrings convention.

- **Category:** layout
- **Activation:** policy — style or a package override sets module_docstrings to require or forbid.
- **Severity when active:** error

## Why

A package chooses one module-docstring convention. require: a consistent module introduction helps readers understand each file's responsibility, so every analyzed production module needs a non-empty initial docstring, including empty files, __init__.py and __main__.py; comments, later strings, bytes, f-strings, blank docstrings and class/function docstrings do not satisfy it. forbid: some projects keep module descriptions in their architecture documentation, so any initial docstring is reported, including empty strings. allow explicitly exempts a nested package; an omitted policy adds no requirement. Separately discovered tests and excluded files are unaffected.

## Bad

```python
# module_docstrings: require
VALUE = 1
```

## Good

```python
"""Constants for the calculation service."""
VALUE = 1
```

## How to fix

Add a useful module docstring before imports and other statements under require; remove or move the module introduction under forbid. Mark an intentional file exception with # smelt: ignore-file[SMT309] -- reason. No documentation is generated or deleted automatically.

## Config

- `style.module_docstrings`
- `style.overrides`

Explain it in the terminal with `smelt explain SMT309`.
