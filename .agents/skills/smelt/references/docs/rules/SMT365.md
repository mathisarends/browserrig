# SMT365 cross-module-private-attribute

Code accesses a private attribute owned by another module or package.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning

## Why

Accessing a collaborator's private fields or methods couples the caller to implementation details. Unlike Ruff SLF001, this opt-in review reports only accesses whose receiver and defining project class are statically known. Same-module cooperation is allowed. Reads, writes, calls, updates and deletes are checked, including self.log._images. Direct accesses on the method receiver to its own or inherited members are allowed. Evidence comes from parameter/variable annotations, direct constructor assignments, stable local aliases, class/instance fields, property return annotations and bounded single inheritance. Import aliases, relative imports and static facade re-exports resolve to the defining class. Dunders, tests, unresolved receivers/members, unknown factories, inherited lookup across multiple/unknown bases, arbitrary class decorators, local imports, comprehension/lambda bodies and closure/global-variable flow are skipped. Rebound parameters and locals are conservatively left unresolved; no control-flow narrowing, runtime dispatch or analyzed code execution is used.

## Bad

```python
# app/client.py
from app.session import SessionLog
def persist(log: SessionLog):
    return log._images.retain()
```

## Good

```python
# app/client.py
from app.session import SessionLog
def persist(log: SessionLog):
    return log.retain_images()
```

## How to fix

Expose a meaningful operation on the owning class, or pass a deliberate public dependency to the caller. Do not merely rename or wrap internal state to silence the report. Preserve evaluation order, exceptions and side effects. No automatic rewrite is performed. Enable rules: {cross-module-private-attribute: warning} or select SMT365. structure.private_attribute_boundary defaults to module; package permits cooperation between modules of the same immediate Python package. Closest-package contract overrides and reasoned suppressions are supported. Boundary options alone do not activate the rule.

## Config

- `rules`
- `structure.private_attribute_boundary`
- `structure.contracts`
