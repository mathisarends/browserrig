# SMT358 prefer-named-duration

A timeout or delay is written as an inline number.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning

## Why

asyncio.timeout(2.5) at two call sites drifts apart as soon as one of them is tuned, and the bare number hides its unit and purpose. Ruff's PLR2004 only covers comparisons. This opt-in review reports int and float literals passed as the duration of asyncio.timeout, asyncio.sleep, asyncio.wait_for, asyncio.wait, time.sleep and the anyio and trio sleep and timeout scopes, resolved through imports and aliases, and literals added to a clock reading such as loop.time() + 10 or time.monotonic() + 10. sleep(0), which yields control instead of waiting, and tests are not checked.

## Bad

```python
async with asyncio.timeout(2.5):
    await page.settle()
```

## Good

```python
SETTLE_TIMEOUT_SECONDS = 2.5

async with asyncio.timeout(SETTLE_TIMEOUT_SECONDS):
    await page.settle()
```

## How to fix

Move the value into a module constant or configuration field whose name states its purpose and unit, and reuse it at every call site that means the same wait. No automatic rewrite is performed. Enable rules: {prefer-named-duration: warning}, or select SMT358.
