# Smelt policy decisions

[Back to development](development.md)

Smelt is pinned to `smelt-cli==0.12.0` in the development dependencies and
`uv.lock`. Hooks use `uv run --locked`; CI installs that same lockfile before
running Smelt. The editor schema and bundled skill are generated by this version.

Adopted source and test conventions are errors. Only SMT108, SMT110 and SMT322
remain visible review hints after the complete audit below. The debt file stays
empty; no threshold, source exclusion or suppression is added for this stricter
review. Breaking API changes are allowed and migrated with their callers.

## 0.10.0 to 0.12.0

All six new rules from 0.11.0 and 0.12.0 are adopted. The 0.11.1 change to package
API checks is also reviewed: discovered tests now participate in SMT107, SMT108
and SMT319. Report schema 2, configuration version 1 and debt version 2 stay the
same. See the [release notes](https://github.com/mathisarends/smelt/blob/v0.12.0/CHANGELOG.md).

| Rule | Decision | Reason and application |
| --- | --- | --- |
| SMT110 `module-import-fanout` | Hint via `structure.max_module_imports: 8` | Review modules that coordinate more than eight direct project dependencies, including siblings. The budget identifies concentrated integration work alongside the existing layer allowlists; it is not a correctness boundary. Facades and declared composition roots retain the documented exemptions. The adoption scan identifies 15 modules, including `browser.chrome`, `choreography.plugin`, `observation.plugin` and `tools.execution.plugin`. Importing their own facade would introduce initialization cycles, and moving imports alone would conceal rather than reduce their work. Keep these visible for responsibility-level review. |
| SMT363 `complex-comprehension` | Error, default one-loop limit | Refactor all initial findings. Explicit loops separate filtering, mapping and collection assembly; named predicates express world selectors, host matching and preview visibility. `chain.from_iterable` preserves streaming flattening for offscreen controls, alerts and image refs. Geometry still visits corners in the same order, CSV still pads short rows, and record copies remain conditional. No threshold override or suppression is needed. |
| SMT364 `constructor-logic` | Error, default two-decision limit | Refactor all 16 candidates into explicit validation, normalization, serialization and index-building operations. Constructors call those operations before assigning their results; guards still reject invalid inputs before activation. Keep exception types, validation order, separate policy defaults and the composition-root budget decisions. The complete mapping is listed below. |
| SMT365 `cross-module-private-attribute` | Error, default module boundary | This complements the existing private-symbol-import rule by enforcing ownership of statically known private fields and methods. No package-wide relaxation is needed. The adoption scan finds no violations. Unknown receiver types and ambiguous inheritance remain outside the rule's static evidence; a clean scan does not prove all accesses safe. |
| SMT366 `comprehension-in-call-argument` | Error | Name eager collections before passing them to another operation, consistent with the existing await-in-call-argument convention. All six initial findings are repaired: normalized connection headers, frame clients, element-ref lookup, canvas element indices, upload paths and unique todo IDs. Generators remain lazy; the rule is the released 0.12.0 version, without unreleased aggregate-call detection. |
| SMT367 `excess-private-definitions` | Error, default limit twelve | Split `observation.render` and `files.spreadsheets` into packages with explicit internal responsibilities. Rendering separates snapshot assembly, headers, sections, elements and text formatting. Spreadsheet readers separate XLSX, XLS, ODS and delimited input from shared cell-range selection and table formatting. Each `__init__.py` only re-exports the existing entry points: `render`, or the four `read_*` functions. Behavioral regression tests cover combined world invalidation selectors, falsy
initial and ongoing readiness policies, and TOTP settings rejected before seed

receipt tests continue to exercise the extracted operations through public behavior.

### Test imports after 0.11.1

Ordinary class/function imports use the existing public facades, including root
re-exports. Tests constructing extraction results use the exported `PageContent`
under the local name `Extraction`, which is the same class. No production export
is added just to satisfy a test. Three kinds of exceptions stay on their specific
import statements, each with its concrete purpose:

- Unit seams test internal algorithms or value bookkeeping independently of
  plugin activation: process cleanup, world and network state, index workers,
  redaction, fingerprints, deltas, scene/receipt projection, recording spans and
  compaction. Publishing those implementation types would enlarge the supported
  API without a production consumer. Module imports used for monkeypatching stay
  at the owning lookup site so the tests still replace the real dependency.
- SMT107 in 0.12.0 mistakes `from browserrig.observation import capture, render`
  for imports of the same-named modules. Both names are explicitly exported
  functions. Keep the facade calls and explain the false positive at the import;
  replacing them with implementation imports or changing the API would defeat
  the contract being tested.
- SMT319 asks the facade identity test to import `BrowserPerception` and its
  `PerceptionExport` alias from the root. That would compare one import with
  itself and stop checking the observation facade. Retain the two import paths.

SMT107 and SMT319 remain errors everywhere else. SMT108 can still suggest
bundling internal imports in focused tests; those hints do not justify exporting
implementation details. No rule is disabled or lowered, no test directory is
excluded and no new debt is recorded for this migration.

## Strictness review

The review covers every previous `warning`, `hint` and `off` entry, plus the
policy-activated import hints. The pre-change scan contained 134 hints and no
warnings. Empty scans still receive a decision: no current finding is not a reason
to leave a useful convention unenforced.

| Rules promoted to error | Decision and implementation |
| --- | --- |

| `implicit-optional-default` | Optional values default on `None`, not on falsiness. No open findings; explicit intentional truthiness can be justified at the affected statement. |
| `prefer-callable-instance` | `ProjectStatus`, `_ExtractFrame`, `IsOccluded`, `InvokeTool` and `ResolveDomElement` expose their operation as `__call__`, preserving construction and call-time inputs. The two named-interface candidates explicitly implement their existing `InputTargets` and `References` protocols; their method names are protocol contracts. |
| `caller-before-callee`, `redundant-module-name` | Reorder workspace/index helpers, document scroll queries and overlay presentation after checking definition-time dependencies. The refactored parser/strip methods follow the same order. No module-name candidates exist. |
| `unnecessary-future-annotations`, `prefer-match-type-dispatch`, `duplicate-literal-type` | Enforce the existing annotation, dispatch and shared-vocabulary conventions. Literal aliases must still describe the same domain; coincidentally identical value sets can receive a specific exception. No open findings. |
| `information-hiding`, `secret-settings-field`, `test-only-public-attribute` | Enforce private implementation state and secret-safe configuration. Smelt already preserves attributes of explicitly exported classes, including `Tab` and `ChromeBrowser`; hypothetical external readers therefore do not justify leaving the whole rule as a warning. |
| `missing-interface-docstring`, `missing-broad-except-reason` | Interfaces state implementer behavior; broad handlers explain the boundary being protected. Existing contracts and handler reasons pass. |

| `test-without-outcome-check`, `test-only-checks-possibly-empty-data` | Require observable outcomes and prevent empty collections from making tests pass vacuously. No open findings. |

| `facade-export-gap`, `missing-dataclass-option`, `prefer-project-base-class` | Enforce findings when their corresponding package policies apply. Existing recording-value and project-base policies remain scoped to their intended contracts. |
| `unused-suppression`, `resolved-debt` | Stale exceptions and resolved baseline entries also fail as errors. The debt file remains empty. |

The public resolver change is deliberate: import `ResolveDomElement` and use
`await scope[ResolveDomElement](tab, ref)` instead of `DomElements.resolve`.
Production tools, test providers, public facades, documentation and the changelog
migrate together. Other backends keep the named `References.resolve` contract.

### Three retained review hints

These decisions are based on the actual receivers and imports, not compatibility
or the amount of work a refactor would require. A local alias, extra forwarding
method or export used only to reduce a count would not improve ownership. Hints
remain visible; none is suppressed or entered as debt.

## Earlier adoption: 0.8.0 to 0.10.0

The previous upgrade reviewed all fifteen rules added in 0.9.0 and 0.10.0.

| Rule | Decision | Reason and application |
| --- | --- | --- |
| SMT348 `missing-interface-docstring` | Error | Protocol methods state implementer contracts, including units, missing targets and unavailable data. Class-level descriptions alone leave individual operations ambiguous. |
| SMT349 `stateful-dataclass` | Error | `_Parser`, `_Strip`, `_Runner` and `MemorySummarizer` are controllers with private scratch/cache/retry state, not records with generated equality and a public field initializer. They now initialize and own that state explicitly; passive state records remain dataclasses. |
| SMT350 `missing-broad-except-reason` | Error | Broad handlers explain the boundary they protect: navigation fails closed, arbitrary host callbacks finish a failed handoff, and failed actions produce receipts. |
| SMT351 `missing-dataclass-option` | Package policy | Require `frozen` and `slots` for recording's result/segment/span value records. Other packages mix values and mutable activation state; a project-wide requirement would conflate their lifetimes. `kw_only` would change existing constructor calls and is not imposed. |
| SMT352 `duplicate-function` | Error | Native and DOM typing share slip feedback, including the security-sensitive rule that secret-adjacent text is never echoed. Keep their input workflows separate. |
| SMT353 `prefer-project-base-class` | Package policy | Use `browserrig.core.Options` instead of direct Pydantic `BaseModel` inheritance. `_Manifest` has one local, reasoned exception: extraction progress must remain mutable, while `Options` is frozen. |
| SMT354 `prefer-domain-exception` | No global policy | Browser failures already use `BrowserError`. Geometry, reader arguments and retention configuration intentionally raise standard `ValueError`/`TypeError` for invalid caller input. Converting them would change callers' exception handling. |
| SMT355 `duplicate-class-name` | Error | The Markdown extraction result is named `ExtractedContent`, matching its existing facade export. `PageContent` remains the capture backend's page model; both facade names stay available. |
| SMT356 `duplicate-narrowing-assert` | Error | The readiness runner now keeps a validated context/strategy pair and passes the initialized strategy into probes. Tabs cleanup, readiness hook dispatch and recording output use one explicit resource check each, raising domain errors even under `python -O` and before resource allocation where applicable. |
| SMT357 `missing-duration-unit` | Error | Browserrig's numeric durations name their units: `timeout_seconds`, `duration_seconds`, `poll_interval_seconds`, `typing_interval_seconds` and `original_duration_seconds`. Configuration, event payloads, tool schemas, overlay consumers and callers migrate together. Existing `_ms` fields and upstream CDP/HTTP/asyncio/animation parameter names keep their contracts and conversions. |
| SMT358 `prefer-named-duration` | Error | Name Chrome startup/shutdown budgets, frame setup, DOM seeding, diagnostics and reveal delays by purpose and seconds. Values and evaluation points are preserved; unrelated operations keep separate budgets even when their values match. |
| SMT359 `nested-conditional-expression` | Error | Explicit branches make model selection, screenshot regions, file classification, cell rendering, fingerprints and element states easier to inspect while preserving branch order and lazy evaluation. |
| SMT360 `mutable-field-in-frozen-dataclass` | Error | Frozen dataclasses should not accidentally expose mutable collections. Only `CdpEndpoint.headers` has a reasoned field-level exception for its transport-compatible, mutable `dict`; built-in producers create fresh dictionaries. The rest of the project remains checked. |
| SMT361 `parallel-record-fields` | Error | Pair related fields in records unless an explicit column-store contract justifies a local exception. The current scan has no candidates; upstream CDP storage does not require a project-wide relaxation. |
| SMT362 `loop-invariant-collection` | Error | Reuse lookup collections when the rule establishes stable immutable inputs. Preserve guards and empty-loop evaluation. Limited inference narrows coverage rather than requiring a lower severity; the scan has no candidates. |

Rules without a corresponding architecture policy remain outside this review.
Configured severity alone does not activate a policy-based check: for example,
`facade-export-gap` has no findings because no `export_at` budget is configured.
Do not add debt or weaken existing checks merely to make an upgrade pass.
